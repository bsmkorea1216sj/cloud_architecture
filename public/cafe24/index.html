STEP 02 · PPT 11–16 · 검토용 개정안

이미지 기반 AI 상품 분류·가공 자동화

교육 실습은 CSV 수동 입력보다 Google Drive 지정 폴더에 상품 이미지를 넣는 것부터 시작합니다. 로컬 PC의 감시 프로그램이 새 이미지를 확인하고 Photoshop에서 가공한 뒤, 결과를 다운로드 폴더에 카테고리별로 정리합니다. 그 다음 카페24 등록 데이터와 연결합니다.

교육 설계 흐름(구현 여부 미확인)입니다. Codex는 이 자동화 코드를 개발·수정하는 도구이고, 지속적인 폴더 감시와 Photoshop 실행은 별도 로컬 프로그램·자동화 설정이 담당합니다.

① 전체 이미지 처리 워크플로우

Google Drive 지정 폴더
상품 원본 이미지 투입→로컬 자동 감지
동기화·감시 프로그램→Photoshop 자동 가공
크기·배경·파일명 등→Downloads 폴더
카테고리별 분류·저장→Cafe24
검수 후 등록

② 실습 단계별 설명

단계자동화 대상수강생 확인 사항
1Drive의 지정 입력 폴더에 JPG/PNG 상품 이미지 추가상품 ID나 규칙에 맞는 원본 이미지인가?
2로컬 PC에서 신규 파일 감지 및 다운로드/동기화중복 감지 없이 파일이 수신됐는가?
3Photoshop 액션·스크립트로 이미지 가공크기, 배경, 파일 형식이 기준에 맞는가?
4이미지 또는 상품 정보로 카테고리 판정, Downloads 아래 폴더별 저장잘못 분류된 상품은 검수 대기인가?
5상품명·카테고리·가공 이미지 경로를 등록용 데이터로 정리필수 항목과 카페24 카테고리 ID를 확인했는가?
6승인된 상품에 한해 Cafe24 등록 진행DRY_RUN 미리보기 → 관리자 승인 → 실제 API 연동 여부 확인

③ 폴더 구성 예시

Google Drive/
  상품이미지_입력/              ← 원본 이미지를 넣는 곳

내 PC/Downloads/
  cafe24-processed/
    의류_상의/
    생활_주방/
    생활_욕실/
    검수필요/
  cafe24-registration-preview.csv
실제 Google Drive 폴더명과 Photoshop 액션 설정, Downloads 경로는 사용하는 PC 환경에 맞춰 지정합니다. 위 폴더명은 예시입니다.

④ Codex에 입력할 개발 지시문

로컬 Windows PC에서 작동하는 카페24 상품 이미지 자동화 프로그램을 설계해 주세요.

1. Google Drive 데스크톱 동기화 폴더 안의 상품이미지_입력에 새 JPG/PNG가 나타나면 감지합니다.
2. 전송이 완료된 파일만 처리하고, 동일 파일 중복 처리 방지 및 처리 로그를 남깁니다.
3. 설치된 Adobe Photoshop의 액션/스크립트 자동화를 호출해 가공 이미지를 만듭니다.
4. 사전에 정의된 카페24 카테고리 목록에 따라 상품 또는 이미지를 분류합니다. 불확실하면 검수필요로 보냅니다.
5. 가공 이미지는 Downloads/cafe24-processed 아래 카테고리별 하위 폴더에 저장합니다.
6. 상품명·카테고리·이미지 파일 경로를 등록 미리보기 CSV/JSON으로 정리합니다.
7. 기본값 DRY_RUN=true로 실제 카페24 상품 등록 API는 호출하지 않습니다.
8. 처리 오류, Photoshop 미실행, 파일 잠금, 중복, 분류 실패를 안전하게 기록합니다.

먼저 로컬 폴더의 샘플 이미지로만 테스트할 수 있는 모의 모드를 구현해 주세요.
Photoshop 연동 방식과 실행 가능 여부는 설치 버전과 지원 스크립트 기능을 확인한 뒤 적용해 주세요.
API 키와 OAuth 토큰은 코드·GitHub·로그에 포함하지 마세요.

⑤ 강사가 반드시 설명할 구분

  • Codex: 자동화 프로그램을 설계·개발·수정합니다. Codex 자체가 상시 파일 감시 서비스는 아닙니다.
  • Google Drive: 상품 이미지 입력 위치입니다. 로컬 감시는 동기화 설정이나 별도 감시 프로그램이 필요합니다.
  • Photoshop: 이미지 가공을 맡으며, 자동 처리는 설치 환경에 맞는 액션·스크립트가 필요합니다.
  • 다운로드 폴더: 가공된 상품 이미지를 카테고리별로 보관하고 등록 자료를 생성합니다.
  • Cafe24: 검수와 관리자 승인 후 실제 등록합니다. 본 기초 실습에서는 미리보기까지만 다룹니다.
완료 기준: Drive 폴더에 이미지를 추가했을 때 처리 대상이 감지되고, Photoshop 가공 결과가 카테고리별 Downloads 폴더에 나타나며, 카페24 등록용 미리보기 목록까지 생성되는 과정을 설명할 수 있습니다.

STEP 04 · PPT 19–20

GCP Cloud Run 배포 구조

백엔드 API를 Cloud Run에서 실행하는 과정을 이해합니다. 실제 배포는 실습 계정과 예산 설정이 준비된 경우 진행합니다.

GitHub→빌드·테스트→컨테이너→Cloud Run→HTTPS API
API 경로기능
GET /health서비스 상태 확인
POST /classify샘플 상품 분류
POST /products/preview등록 미리보기·검증

Codex 구현 지시 예시

FastAPI로 /health, /classify, /products/preview를 가진 교육용 서버를 만들어 주세요.
기본값 DRY_RUN=true로 외부 Cafe24 API는 호출하지 않습니다.
입력 검증, pytest 테스트, Dockerfile 및 Cloud Run 배포 안내를 포함하세요.
시크릿은 소스에 포함하지 마세요.
GCP 예산 알림은 비용을 자동 차단하지 않습니다. Cloud Run 인증, 최대 인스턴스 및 로그 보존을 확인해야 합니다.

STEP 05 · PPT 21–23

Cafe24 상품 등록 미리보기

기본 교육에서는 실제 쇼핑몰에 전송하지 않습니다. 분류·필수값 검증·중복 검사·승인 단계를 학습하는 모의 실습입니다.

검수 완료→등록 미리보기→승인→권한 확인→실제 등록(심화만)

교육용 미리보기 JSON

{
  "internal_sku": "DEMO-001",
  "product_name": "면 반팔 티셔츠",
  "category_label": "의류/상의",
  "review_status": "approved",
  "dry_run": true
}
위 JSON은 교육용 개념 예시이며 실제 Cafe24 API 요청 스키마가 아닙니다. 최신 공식 Admin API 문서의 엔드포인트·필수 필드·권한·호출 제한을 별도로 검증해야 합니다.
